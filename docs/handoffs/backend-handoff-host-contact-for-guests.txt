# Backend handoff: Host contact for guests

Frontend repo: `sdi_trips`. This document specifies Supabase RPC and notification changes required for gating owner/host contact information.

## Product rules

1. **Public listing pages** must never expose owner email or phone (SummerRent + EventVenue).
2. **After a guest reservation is confirmed**, include host name, email, and phone in the confirmation channel (email **or** SMS — whichever your pipeline sends for that booking).
3. **Reservation lookup** (`get_reservation_by_code`, `get_booking_by_manage_token`) returns host contact only when booking status is `confirmed` or `completed`.

Listing types: `SummerRent` (app-main), `EventVenue` (app-alt). Both use the same RPC parameter `p_listing_type` / `listing_type`.

---

## 1. Public property RPCs — strip owner PII

### Functions

- `get_public_summer_rent_property_by_id`
- `get_public_summer_rent_properties`
- `get_public_event_venue_properties` (and `get_public_event_venue_property_by_id` if it exists)

### Required behavior

- Do **not** return owner/member email, phone, or direct contact fields in any column.
- `OwnerId` may remain for internal joins; frontend ignores contact fields on public responses.
- If host display name or avatar is added later, that is acceptable; email/phone are not.

---

## 2. Reservation lookup RPCs — add host contact when confirmed

### `get_reservation_by_code`

**Parameters (existing):**

- `reservation_code` (text)
- `p_listing_type` (`SummerRent` | `EventVenue`)

**When `Bookings.Status` maps to `confirmed` or `completed`**, include host contact on the `reservation` object. Omit host contact for `pending_confirmation`, `pending`, `cancelled`, and expired lookups.

**Suggested fields** (camelCase in JSON payload; frontend also accepts snake_case):

```json
{
  "success": true,
  "reservation": {
    "bookingId": "uuid",
    "reservationCode": "RSV-ABC123",
    "propertyId": "uuid",
    "propertyTitle": "Beach House",
    "checkIn": "2026-06-01",
    "checkOut": "2026-06-07",
    "status": "confirmed",
    "guestName": "Jane Guest",
    "guestEmail": "guest@example.com",
    "guestPhone": "+59899123456",
    "canCancel": true,
    "isExpired": false,
    "listingType": "SummerRent",
    "hostName": "Ana Host",
    "hostEmail": "host@example.com",
    "hostPhone": "+59899988777"
  }
}
```

**Alternative nested shape** (also supported by frontend):

```json
"hostContact": {
  "name": "Ana Host",
  "email": "host@example.com",
  "phone": "+59899988777"
}
```

**Data source:** `EstateProperties.OwnerId` → Members (or your owner table). Use the same display name logic as host profile elsewhere.

**Pending example** (no host fields):

```json
{
  "success": true,
  "reservation": {
    "status": "pending_confirmation",
    "hostName": null,
    "hostEmail": null,
    "hostPhone": null
  }
}
```

### `get_booking_by_manage_token`

Same host fields on the nested `booking` object when status is `confirmed` or `completed`:

```json
{
  "success": true,
  "booking": {
    "bookingId": "uuid",
    "reservationCode": "RSV-ABC123",
    "propertyTitle": "Event Hall",
    "checkIn": "2026-08-10",
    "checkOut": "2026-08-10",
    "guests": 80,
    "status": "confirmed",
    "canCancel": true,
    "hostName": "Venue Owner",
    "hostEmail": "owner@example.com",
    "hostPhone": "+59899111222"
  }
}
```

## 3. Confirmation notifications

### Trigger

After successful `confirm_booking_from_hold` when the resulting booking status is **confirmed** (status integer `1` in `Bookings`).

Applies to guest holds for `SummerRent` and `EventVenue`.

### Email

Update `send-booking-confirmation` and/or whatever `confirm_booking_from_hold` invokes today.

**Include in template:**

| Field | Source |
|-------|--------|
| Guest name | Guest payload / booking |
| Reservation code | `Bookings` / generated code |
| Manage link | manage token URL |
| Property title | Listing |
| Check-in / check-out | Booking dates |
| **Host name** | Owner member |
| **Host email** | Owner member |
| **Host phone** | Owner member |

**Sample body block:**

```
Your reservation is confirmed.

Reservation code: RSV-ABC123
Property: Beach House
Dates: Jun 1, 2026 – Jun 7, 2026

Host contact:
Ana Host
Email: host@example.com
Phone: +598 99 988 777

Manage your booking: https://…/reservation-lookup?token=…
```

### SMS

If you send a post-confirmation SMS (distinct from `booking-send-otp`):

- Append host name + phone (required).
- Add email if message length allows.
- **Never** include host contact in OTP or hold-expiry SMS.

**Sample SMS:**

```
SDI Trips: Booking RSV-ABC123 confirmed. Beach House Jun 1–7. Host: Ana Host, +59899988777, host@example.com. Manage: https://…
```

### Channel selection

Keep existing rules (e.g. email when guest email present, SMS when phone-only). Frontend does not choose the channel.

### `send-booking-confirmation` (legacy path)

If still invoked from member `createBooking` with `{ bookingId }`, load host contact by `bookingId` the same way and include in the Resend template.

---

## 4. Security checklist

- [ ] Public property RPCs return no owner email/phone
- [ ] Lookup RPCs return host contact only for `confirmed` / `completed`
- [ ] OTP SMS (`booking-send-otp`) unchanged — no host PII
- [ ] Cancelled / pending bookings do not leak host contact via lookup

---

## 5. Frontend mapping reference

After deploy, frontend reads:

| RPC field | Maps to |
|-----------|---------|
| `hostName` / `host_name` | `hostContact.name` |
| `hostEmail` / `host_email` | `hostContact.email` |
| `hostPhone` / `host_phone` | `hostContact.phone` |
| `hostContact` object | `hostContact` as-is |

Files: `src/services/bookingService.ts` (`mapReservationFromLookupPayload`, `mapHostContactFromPayload`), `src/types/index.ts` (`HostContactInfo`, `ManageBookingView`).

## 6. Verification

1. Call `get_public_summer_rent_property_by_id` — response has no owner email/phone.
2. Call `get_reservation_by_code` for pending booking — no host fields.
3. Call `get_reservation_by_code` for confirmed booking — host fields present.
4. Complete `confirm_booking_from_hold` — confirmation email/SMS includes host block.
5. Repeat for `p_listing_type = 'EventVenue'`.
